# <Feature>: feature docs

The tracked record of this feature as built: what it does, why it works this way, and what is still unverified.

| File | Read it when |
|---|---|
| [overview.md](overview.md) | You need context: the problem, what was built and where, how the parts connect, and the feature's terms |
| [decisions.md](decisions.md) | You are about to change behavior. Each decision `Dn` has a reason; a change builds on it or supersedes it |
| [tickets.md](tickets.md) | You need acceptance criteria, test evidence, or the list of unfinished work |
| `sources.json` | Never, unless you maintain these docs. The feature-docs script writes it to notice when inputs change |

Project-wide terms and architecture decisions live in the repo's glossary and ADRs; these docs link to them rather than repeat them.
